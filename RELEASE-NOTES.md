ScreenCapture 0.7.1 fixes a virtual-camera format incompatibility with native WebRTC capture and pairs the camera name with the VB-CABLE audio input.

- The previous camera only advertised RGB32, which OBS accepts but the native WebRTC DirectShow backend does not enumerate as a supported format. The camera now prefers RGB24, retaining RGB32 compatibility and 1920×1080 at 60 FPS.
- Clients can initialise at 30 FPS and renegotiate to 60 FPS. Format queries return the selected format, connected stopped graphs can be reconfigured, and capture timing follows the negotiated frame rate.
- On the receiving PC, **Discord · приём → Связать устройства** updates the installed camera and names the chosen cable's recording endpoint **ScreenCapture Camera Audio (VB-CABLE)**. A custom camera name is preserved and included in the paired audio name. Stable endpoint IDs and the VB-Audio vendor interface name are retained. Chromium's camera/audio grouping heuristic can match these names; Discord's own saved selection may require choosing the paired audio input once.
- Before installing VB-CABLE through our button, all six Windows playback/recording default roles are saved. If the installer switches them to the cable, previous active devices are restored, including a recovery attempt after reboot. This cannot recover unknown defaults from older installations. A switch to another non-cable device is preserved.
- No camera/cable installation on the controlling gaming PC. No new driver installation through the updater. Existing camera registration is refreshed on the receiving PC; fully quit and reopen Discord after updating so it loads the new DLL.
- Added bounded per-process camera diagnostics with negotiated formats and frame counters. Frames, audio and private screen content are not logged.

Validation: isolated DirectShow device enumeration, RGB24/RGB32 1080p60 and RGB24 30 FPS, connected format changes, exact red/blue channel and orientation checks, changing-frame cadence, synthetic 1440p NDI → GPU resize → camera, audio default-restore rules, read-only Windows 11 PolicyConfig ABI checks, UI and update regression tests. These are local tests, not confirmation of a successful Discord broadcast or its automatic audio selection. VB-CABLE was not installed on the gaming PC.

File drag/drop remains unfinished and was reported not working on the actual PCs. Use Ctrl+C / Ctrl+V; this update does not claim to fix dragging. SDR colour processing and the NDI sender are unchanged.
